CSONET Research presentation

Streaming Algorithms for
Monotone k-Submodular Maximization
under Fairness Constraints

Dung T. Pham · Tan D. Tran · Canh V. Pham

ORLab, Phenikaa University, Hanoi, Vietnam

Good morning everyone. Today, I will present our work on streaming algorithms for monotone k-submodular maximization under fairness constraints. We study how to select and label arriving elements while satisfying lower and upper quotas for every label. I will explain the feasibility framework, our two streaming algorithms, and their theoretical and empirical trade-offs. Source: manuscript, pp. 1–3.

02 · Model

Monotone k-submodular maximization

maximize f(S₁, …, Sk)

ℓi ≤ |Si| ≤ ui for every label i

∑i |Si| ≤ B total budget

Si ∩ Sj = ∅ for i ≠ j

Monotonicity

Adding a labeled element never reduces the value.

Diminishing returns

For compatible assignments s ⪯ t and e ∉ supp(t):

Δi(e | s) ≥ Δi(e | t)

Assumptions: n ≥ B ≥ 1, 0 ≤ ℓᵢ ≤ uᵢ, and ∑ᵢ ℓᵢ ≤ B ≤ ∑ᵢ uᵢ. Theory assumes exact value-oracle access.

The objective takes a tuple of disjoint sets. Each coordinate corresponds to one label. Monotonicity means that adding a labeled element cannot hurt. The diminishing-returns property applies when one assignment extends the other without changing existing labels. We maximize this objective under lower and upper label quotas and a total budget. Under the assumptions shown here, monotonicity allows an optimal solution with exactly B selected elements. Source: manuscript, Section 3, pp. 5–8.
03 · Challenges

Lower quotas and conflicting labels

A

Budget must leave room for deficits

Early selections can consume the slots that other labels still need.

A partial assignment must remain completable.

B

The same element can have two labels

Algorithm: (e, 1)

Optimum: (e, 2)

The pair-set union is not a valid k-set.

The analysis must compare assignments without creating label conflicts.
There are two obstacles. First, lower quotas constrain future choices. A state that respects upper bounds can still leave too few budget slots to meet all lower quotas. Second, our assignment and an optimal assignment may give different labels to the same element. Combining their pair sets would assign the element twice and leave the domain. This prevents a direct transfer of analyses that rely on ordinary set unions. Source: manuscript, pp. 2, 5, 14–15.
04 · Key idea

Fair extendability

A partial assignment only needs to admit a fair completion.

|Si| ≤ ui ∀i and ∑i max{|Si|, ℓi} ≤ B

Illustrative example · k = 3 · B = 9 · ℓ = (2, 2, 2) · u = (6, 6, 6)

Element–label pairs + quota matroid characterize extendability for valid k-sets.
The key invariant is fair extendability. For each label, reserve the larger of its current count and its lower quota. The sum of these reserved counts must fit the budget, and no upper quota may be exceeded. In the example, counts four, one, zero require at least eight total slots. Counts six, one, zero require ten and cannot fit a budget of nine. The quota matroid characterizes this invariant on element-label pairs. The algorithm separately preserves the valid k-set domain, so each element has at most one label. Source: manuscript, Lemma 3.2, pp. 7–8. Numerical example constructed for this presentation.
05 · Completion

A shared buffer completes the assignment

min{n, 2B}first stream elements retained
  1. Keep the current assignmentPreserve every selected element–label pair.
  2. Fill remaining quota deficitsUse distinct unused elements from the buffer.
  3. Fill the remaining budgetRespect every upper quota and reach size B.
No extra pass · All quotas satisfied · Objective value never decreases
Both algorithms use the same deterministic completion procedure. We retain the first min of n and two B elements. A maintained state contains at most B elements, so this buffer always contains enough unused elements to complete it. We first meet remaining lower quotas and then fill the budget within upper capacities. Completion preserves the maintained assignment and cannot reduce its value because the objective is monotone. The buffer bound is sufficient for this construction. Source: manuscript, Lemma 4.1, p. 9.
06 · One pass

OPFSA

Deterministic selection with quota-preserving replacements

  1. Maintain geometric value guessesEach lane stores an archive and a live assignment.
  2. Evaluate a new elementCompute marginal gains against the archive.
  3. Accept a sufficiently valuable pairRemove a minimum-weight quota blocker if needed.
  4. Complete and compareReturn the best completed active lane.

Acceptance rule

ai ≥ (1 + √2)θi + εv/B

ai: gain against the archive
θi: frozen weight of the blocker
v: value guess

Proof intuition

Frozen weights grow along replacement chains, allowing archive costs to be charged to the final live solution.

OPFSA scans the stream once and runs several value-guess lanes in parallel. In each lane, the archive records accepted pairs and their frozen marginal gains. The live solution remains fair-extendable. When insertion is blocked, the algorithm identifies a minimum-weight quota blocker. The new gain must pay a multiplicative replacement cost plus an additive threshold. Geometric growth along replacement chains controls the total archived weight. The analysis also handles label conflicts without taking an invalid union. Source: manuscript, Algorithm 1 and Section 4.1, pp. 9–15.
07 · Multiple passes

MPFSA

Decreasing thresholds with balanced random label choices

  1. Find the singleton scale MA preliminary pass also fills the shared buffer.
  2. Replay the fixed stream orderDecrease τ by the factor 1 − ε after each pass.
  3. Sample a feasible labelAccept when the best extendable gain reaches τ.

M, (1 − ε)M, (1 − ε)²M, …

Why randomize the label?

A small linear program finds a distribution that balances expected gain against loss in a coupled comparison solution.

Value guarantee: in expectation

Quota feasibility: every execution

At most B label-distribution LPs. Oracle counts exclude the separate LP-solving cost.

MPFSA assumes a replayable stream in the same fixed order. It begins at threshold M and repeatedly lowers the threshold. For an unassigned element, it evaluates labels that preserve extendability. If the best gain passes the threshold, a small linear program provides a balanced label distribution. This distribution controls the expected loss when we update a coupled feasible comparison solution. Randomness affects the approximation guarantee, while every execution satisfies the quotas after completion. Source: manuscript, Algorithm 2, Lemmas 4.6–4.8, and Theorem 4.2, pp. 15–22.

Common range: 0 < ε < 3 − 2√2. For k = 3 and ε = 0.1, the MPFSA guarantee is 0.3. Exceeding 1/3 requires ε < 1/15.

The algorithms offer different access and storage trade-offs. OPFSA uses one pass with a deterministic approximation of approximately 0.1716 minus epsilon. MPFSA uses multiple passes, linear memory in B plus k, and a stronger expected approximation. For three labels, its leading coefficient is 0.4. The epsilon term matters: with epsilon equal to 0.1, the stated guarantee is 0.3, not a guarantee above one third. Both algorithms return exactly B elements and satisfy all quotas. Common accuracy range for this comparison: zero less than epsilon less than 3 minus 2 square root of 2. Source: manuscript, Table 1 and Theorems 4.1–4.2.

We test k-influence maximization on Email-Eu-core and ca-GrQc using a Weighted-Cascade model. The study fixes three labels, lower quota three and upper quota ten per label, and varies the budget from nine to thirty. All methods share the evaluator, seed, and fixed stream order. Decisions use one hundred Monte Carlo worlds, and a separate bank of one thousand worlds evaluates final values. Each algorithm-budget configuration runs once, so the reported standard errors concern evaluation sampling rather than variation across algorithm runs. Source: manuscript, Section 5, pp. 22–24.

Memory measurements use algorithm-phase Python tracemalloc, rather than full-process peak RSS. These experiments use estimated oracle values.

This chart shows the largest tested budget, not the entire budget sweep. On Email-Eu-core, MPFSA obtains 534.246, compared with 533.860 for Fair-Greedy and 532.127 for Fair-Threshold. On ca-GrQc, MPFSA obtains 578.531, compared with 585.273 and 585.984. OPFSA obtains 478.412 and 531.081. MPFSA is therefore close to the offline baselines in these tests. Fair-Threshold is fastest and uses the fewest oracle calls in the reported implementation, which uses lazy priority-queue refreshes. OPFSA has the highest recorded query counts, memory, and runtimes. A one-pass access guarantee does not imply lower wall-clock time. Avoid claims of statistical superiority from these single-run configurations. Our main contribution is a framework for maintaining fair-extendable assignments in streams. It supports a deterministic one-pass algorithm and a randomized multi-pass algorithm with a stronger expected approximation and low memory. Both satisfy all quotas and use exactly B elements on every execution. Improving the one-pass factor and reducing the multi-pass requirement remain open. Thank you. I welcome your questions. Source: manuscript, Section 6, p. 24. Q&A; reminders: the one-pass bound is not proved tight. Fairness is per label, not fixed input groups. Theorems assume exact oracles, while experiments use Monte Carlo estimates.
